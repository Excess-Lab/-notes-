# «&lt;notes&gt;» — маршрутизатор для сессий

Этот файл читается каждой сессией целиком. Здесь только то, что нельзя нарушить никогда, и куда идти
дальше. Подробности — в `docs/`: открывай файл своей области **до первой правки** в ней, остальные не трать.

`<notes>` — open-source приложение заметок под macOS 27+: Markdown-файлы в папке-git, автокоммит и
отправка на GitHub, поиск по смыслу, надиктовка по хоткею в буфер обмена, задачи в Apple Calendar.
Делается для себя. Подход к работе — тот же, что в «Единстве» ([DECISIONS.md](docs/DECISIONS.md)).

## С чего начать

1. [docs/TASKS.md](docs/TASKS.md) — что в работе прямо сейчас. Чат мог оборваться: продолжай оттуда.
2. [docs/MAKAR.md](docs/MAKAR.md) — как работать с Макаром: как он пишет, как отвечать, что ценит
   и что бесит. Обязательно.
3. Файл области из таблицы ниже.

## Нельзя никогда

- **Своя база с текстом заметок.** Файлы `.md` — источник правды; индекс и кэш — вне хранилища и
  пересобираются из файлов. Хранилище открывается любым другим редактором.
- **Свой сервер и аккаунты.** В сеть — только GitHub (если вошли по коду) и разовая загрузка модели.
- **Трогать чужие файлы в хранилище.** Приложение меняет только то, что меняет человек.
- **Модели в сборке и зависимости без вопроса.** Модели качаются по требованию, новая зависимость —
  только после слова Макара ([docs/CODE.md](docs/CODE.md)).
- **Секреты в коде**, `~/.ssh` и глобальные настройки git. Токены и пинкод — только в Связке ключей.
- **Пуш без слова Макара.** Коммит — сам, когда проверено; вся работа в `Dev` ([docs/GIT.md](docs/GIT.md)).
- **Придумывать интерфейс.** Экраны рисует Макар; свой дизайн — только по его просьбе и на
  согласование ([docs/UI.md](docs/UI.md)). Его фреймы в Figma не править.
- **Закрывать его запуск.** Свои процессы — только по пути `build/…`, не `pkill` по имени
  ([docs/TESTING.md](docs/TESTING.md)).
- **Упоминать Obsidian** — нигде ([docs/DECISIONS.md](docs/DECISIONS.md)).
- **Говорить «должно работать».** Сделано — значит проверено: тестом, снимком, логом. Упало — сказать, с выводом.

## Как сдавать работу

По порядку, без пропусков:

1. сборка без ошибок и без новых предупреждений
2. `cd NotesCore && swift test` — **все** тесты, включая сторожа документации
3. проверка вживую: снимок окна рядом с кадром Figma или сценарий руками ([docs/TESTING.md](docs/TESTING.md))
4. документация: [docs/TASKS.md](docs/TASKS.md) и файл области обновлены в том же ходе
5. коммит — сам ([docs/GIT.md](docs/GIT.md))

## Как ведём работу

- **Не переспрашивать «что делаем дальше».** Закончил — бери следующую из [docs/TASKS.md](docs/TASKS.md)
  и скажи одной строкой, что взял. Остановиться и спросить — только когда дальше решение Макара.
- **Каждая его просьба** сразу ложится строкой в [docs/TASKS.md](docs/TASKS.md) и уходит из неё только
  в «Готово» с коммитом или в «ждёт Макара» с вопросом.
- **Долгая работа — с короткими строками статуса.**
- **Документация коммитится сразу**, отдельным коммитом `Feature Docs / …`, когда тесты зелёные.

## Что и куда записывать

Записывать то, что пригодится следующей сессии и чего не видно из кода и git: решение и причину, подход,
который сработал или провалился, незаконченное.

| Узнал | Куда |
|---|---|
| как Макару удобно работать, его реакция, похвала, раздражение | [docs/MAKAR.md](docs/MAKAR.md) |
| его решение по продукту, «потом», «не надо» | [docs/DECISIONS.md](docs/DECISIONS.md) — с датой и его словами |
| просьба, взятая, законченная или вставшая задача | [docs/TASKS.md](docs/TASKS.md) |
| баг, на который ушло больше получаса | [docs/PITFALLS.md](docs/PITFALLS.md) |
| правило кода или интерфейса | [docs/CODE.md](docs/CODE.md), [docs/UI.md](docs/UI.md) |
| устройство подсистемы | [docs/CONTEXT.md](docs/CONTEXT.md) |
| новый файл | [docs/MAP.md](docs/MAP.md) |
| способ проверки | [docs/TESTING.md](docs/TESTING.md) |

Память сессии (`~/.claude/…/memory`) видит одна машина и одна сессия — туда только то, чего в
репозитории быть не должно. Всё остальное — сюда.

## Документация держит себя сама

- Новая договорённость, решение, грабли, правило — в файл своей области **в том же ходе**.
- Новый файл кода — строкой в [docs/MAP.md](docs/MAP.md). Новый документ в `docs/` — строкой в таблицу выше.
- `NotesCore/Tests/NotesCoreTests/DocsTests.swift` падает, если карта неполная, путь или ссылка в доках
  мёртвые, документ не в таблице, у задачи нет статуса или у журнала нет даты.
- Этот файл — только маршруты и запреты. Подробность сюда не дописывать: она уходит в файл области.
