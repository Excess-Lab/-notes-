# «&lt;notes&gt;» — инструкция по работе в проекте

Прочитай целиком до первой правки. Здесь описаны процесс и правила. Что за продукт и зачем он
нужен — в [docs/PRODUCT.md](docs/PRODUCT.md), как он устроен внутри — в [docs/CONTEXT.md](docs/CONTEXT.md),
порядок работ — в [docs/ROADMAP.md](docs/ROADMAP.md).

**Тяп-ляп не делаем.** Лучше меньше, но доведено до конца и проверено.

Проект только начинается: ниже много пунктов «пока нет». Когда что-то появляется, сразу обновляй
этот файл. Устаревшая инструкция хуже, чем никакая.

## 1. Что это

Open-source приложение для заметок под **macOS** в духе Obsidian. Заметки — локальные Markdown-файлы,
папка — git-репозиторий, правки коммитятся сами. Есть поиск по смыслу (векторный индекс), голосовая
надиктовка на открытой модели по глобальному хоткею (текст копируется в буфер обмена) и задачи
с синхронизацией в Apple Calendar. Аккаунтов и своего сервера нет. Канбана нет: решено. Делается для себя.

- **язык и UI** — Swift, SwiftUI; AppKit там, где SwiftUI не хватает (глобальный хоткей, плавающая панель надиктовки)
- **платформа** — только macOS. Шаблон Xcode пока мультиплатформенный (iOS / visionOS тоже включены), их нужно убрать (ROADMAP, этап 0)
- **данные** — папка-хранилище с `.md` файлами, которую выбирает пользователь
- **git** — `git init` в папке и автокоммиты через libgit2; push в приватный `notes` на GitHub после входа по коду
- **поиск** — эмбеддинги локально (встроенная `NLContextualEmbedding` или маленькая открытая модель — ещё не решено), индекс в SQLite в Application Support
- **надиктовка** — локальный Whisper (WhisperKit или whisper.cpp — ещё не решено), модель скачивается по требованию
- **календарь** — EventKit
- **зависимости** — только Swift Package Manager и только открытые

Где что лежит:

```
<notes>/                  исходники приложения
<notes>/MyApp.swift       точка входа (@main)
<notes>/ContentView.swift пока шаблонный экран
<notes>.xcodeproj         проект Xcode
docs/PRODUCT.md           продукт: функции, принципы, открытые вопросы
docs/ONBOARDING.md        первый вход: шаги, ветки и анимации
docs/CONTEXT.md           устройство: схема, решения по git, поиску, надиктовке, календарю
docs/ROADMAP.md           этапы работ
```

Когда появятся модули, расписывай их здесь по строке на файл или папку, как в примере выше.

### Главные правила продукта

Их нужно знать до любой правки: если нарушить хоть одно, получится другой продукт.

- **Файлы — источник правды.** Текст заметок и задач живёт в `.md` файлах хранилища. Кэш и индекс
  допустимы, но их всегда можно пересобрать из файлов. Своей базы с контентом нет. Хранилище должно
  нормально открываться в Obsidian и любом другом редакторе.
- **Без своего сервера и без аккаунтов.** В сеть ходят только GitHub (если пользователь вошёл по коду) и разовая загрузка модели.
- **Чужие файлы не трогать.** В хранилище могут лежать `.obsidian/`, картинки и что угодно ещё.
  Приложение меняет только то, что меняет пользователь.
- **Лёгкая сборка.** Моделей в сборке нет: Whisper и эмбеддинги скачиваются при включении функции.
  Каждую новую зависимость оценивай и по весу.
- **Индекс поиска — кэш.** Он лежит вне хранилища, его можно удалить и пересобрать из файлов, в git он не попадает.

## 2. Первый запуск

**Шрифты.** Martian Grotesk — SIL OFL 1.1 ([evilmartians/grotesk](https://github.com/evilmartians/grotesk)):
встраивать и распространять можно, текст лицензии лежит рядом, `<notes>/Fonts/OFL.txt`, — не удалять.
В приложении только нужные начертания: xWdUlt (логотип), xWdxBd (заголовки), StdRg и StdMd (текст).

```bash
open "<notes>.xcodeproj"
```

В Xcode выбери схему `<notes>`, назначение **My Mac** и нажми ⌘R. Из терминала:

```bash
xcodebuild -project "<notes>.xcodeproj" -scheme "<notes>" -destination 'platform=macOS' build
```

## 3. Ежедневный цикл

Собрать и запустить (сборка в `build/`, он в `.gitignore`):

```bash
xcodebuild -project "<notes>.xcodeproj" -scheme "<notes>" -destination 'platform=macOS' -derivedDataPath build build
```

```bash
open "build/Build/Products/Debug/<notes>.app"
```

- В приложении есть меню «Отладка» → «Повторить загрузку» (⌘R): сцена загрузки проигрывается заново.
- Проверка вида — снимком окна и сравнением с кадром Figma бок о бок (`screencapture -l <id окна>`,
  id берётся из `CGWindowListCopyWindowInfo`). Для этого у Claude должно быть разрешение
  «Запись экрана» в настройках macOS.
- Тестовое хранилище держи **вне** репозитория: в нём будут свои git-коммиты.

## 4. Как сдавать работу

По порядку, без пропусков:

1. сборка проходит без ошибок и без новых предупреждений
2. тесты — **все**, а не только свои (когда появятся, см. п. 5)
3. проверка вживую: запусти приложение и пройди сценарий руками или через скриншот
4. коммит — только когда попросили

Не говори «должно работать». Работа сделана, когда она проверена: тестом, запуском, логом.
Если что-то упало, так и скажи и приложи вывод.

## 5. Тесты

Пока их нет. План: Swift Testing для логики без UI (разбор Markdown, формат задач, решения
синхронизации). Логику, которую хочется проверить, выноси из вьюх в отдельные типы.

- Названия и комментарии в тестах — по-русски: тест читается как описание поведения.
- В комментарии пиши, что именно ломалось раньше. Иначе через месяц тест выглядит придиркой, и его удаляют.
- **Новый тест проверяется поломкой.** Сломай то, что он охраняет, убедись, что он упал, и верни как было.

## 6. Дизайн

**Интерфейс рисует автор**, Claude его не придумывает.

Макет: [Figma «&lt;notes&gt;»](https://www.figma.com/design/Dver2Yyv9hUj9fSogWAuJ8/%3Cnotes%3E).
Холст разложен по секциям, по одной на флоу: онбординг, заметки, задачи и календарь, надиктовка,
настройки, расшифровка видео. Экраны стоят в ряд. В секции «основа» лежат цвета, стили, иконки и компоненты.

**Эталон — экраны, которые автор переделал сам** (первый — «Первый вход»). Черновики Claude
слишком похожи на типовые настройки macOS. Когда автор говорит «ничего не меняй», его фреймы только читаем.

Правила стиля, которые автор задал сам:

- **Liquid Glass везде** (macOS 26), причём слоями: например, полоса из вертикальных стеклянных
  планок сверху, а под ней отдельный стеклянный лист с контентом, который на неё наезжает.
- **Шрифт — Martian Grotesk.** Заголовки и логотип `<notes>` — xWd xBd (широкий жирный), текст — Std Rg.
  Шрифт меняется в текстовых стилях, а не по слоям.
- **Акцент — коралловый `#E54D33`**, а не синий Apple.
- **Иконки точками, как в «Единстве»** (<notes> — его продолжение). Каждая иконка — матрица круглых
  точек 1×1 с шагом 1. У «Единства» сетка 27×21, у нас меньше: 16×12 внутри компонента 16×16.
  Цвет по умолчанию — `текст/основной`. Зелёный (готово) и акцент (задачи в календаре) задаются
  переопределением в инстансе. В приложении рисовать их тоже точками, а не SF Symbols.
- **Минимум элементов**: одно главное действие на экран, второстепенное — мелкой серой ссылкой.
  Служебных элементов нет: ни кнопок окна, ни индикаторов шагов, ни лишних иконок.
- **Трекинг −7%** во всех текстовых стилях.
- **Весь интерфейс — строчными буквами.** Исключение — то, что ввёл пользователь: текст заметок,
  названия задач, значения в полях, запрос в поиске. Для них есть стили `ввод` и `заметка/*`.
  В коде это значит, что строки интерфейса пишутся строчными сразу. `.lowercased()` к пользовательскому тексту не применяй.

- Пока экрана нет в макете, верстай функционально на системных компонентах macOS, без своих цветов, шрифтов и украшений.
- Когда макет есть, единственный источник размеров — Figma. Числа бери из JSON узла, а не с картинки.
- Смотреть надо кадр целиком: сначала сравни скриншот макета со скриншотом приложения, потом сверяй числа.
- Логику держи отдельно от вьюх, чтобы редизайн не задевал поведение.

## 7. Правила кода

- **Комментарии по-русски и объясняют «почему», а не «что».**
- Имена типов, функций и переменных — по-английски, в обычном стиле Swift.
- Новая зависимость — только после вопроса автору.
- У автора есть опыт веб-сервисов, а приложений нет. Где это помогает, объясняй через параллель с вебом.
- Всё, что связано с macOS-спецификой (песочница, entitlements, разрешения на микрофон, календарь,
  Accessibility для хоткея, подпись), объясняй простыми словами: автор раньше под Mac не писал.
- Секретов в коде нет. В `~/.ssh` и глобальные настройки git приложение не лезет.

## 8. Грабли, проверенные на практике

Сюда пиши всё, на что ушло больше получаса: симптом, причину и как правильно.

**SwiftUI / macOS:**

- **Эффект Glass из Figma ≠ системный `.glassEffect`.** Системное стекло размывает фон и рисует свой обод,
  а Glass в Figma увеличивает и сдвигает то, что под ним, и слегка матует. На планках загрузки вместо
  шахматки выходили белые полосы со швами. Такие места рисуем сами (`GlassSlats`: Canvas, свой слой
  на каждую планку, клип по краям, потом размытие), а не системным стеклом.
- **Тёмная тема системы перекрашивает стекло и заголовок** в серое. Макеты только светлые, поэтому
  стоит `.preferredColorScheme(.light)`; тёмная тема — в ROADMAP «Потом».
- **`.hiddenTitleBar` всё равно резервирует 32 pt** под заголовок, и окно выходит выше макета.
  Автор хочет обычную полосу заголовка с `<notes>`, поэтому окно стандартное: сцена 560×440 под полосой.
- **Слои сверяй по JSON узла Figma**, а не по картинке: маски, поворот (`relativeTransform`),
  что лежит поверх чего. По картинке шапку сделали на всю высоту, а в макете она 66 px с маской.
- Скругления углов сцены не нужны: у окна macOS свои углы.

**Figma через MCP (use_figma):**

- **Цвет из переменной рендерится по «сырому» цвету.** `setBoundVariableForPaint` поверх
  `{color: чёрный}` в редакторе выглядит правильно, а скриншот и экспорт рисуют чёрный (так сайдбар
  стал чёрным). Сырой цвет ставь равным значению переменной.
- **Прозрачность у привязанной заливки теряется.** Сегодняшний день в календаре залился сплошным синим.
  Полупрозрачное делай обычной заливкой с `opacity`, без переменной.
- **`createVector()` создаётся с чёрной обводкой 1px.** Убирай её: `strokes = []`.
- **`resize()` у авто-лейаута ставит FIXED.** Карточка папки схлопнулась до 10px. После `resize`
  заново ставь `primaryAxisSizingMode = 'AUTO'`.
- **Локальные шрифты Figma через MCP не видит**, только свои (Google Fonts, SF Pro).
- **Проверять надо `get_screenshot`, а не `node.screenshot()`.** Внутренний скриншот рендерит стекло иначе.
