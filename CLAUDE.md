# «&lt;notes&gt;» под Windows — маршрутизатор для сессий

Это ветка `Windows`. Здесь `<notes>` переносится на Windows: приложение открывает **то же хранилище**,
что и версия для macOS, и не портит его. Мак-версия — образец поведения и вида, её код здесь не меняется.
Этот файл читается каждой сессией целиком: только то, что нельзя нарушить, и куда идти дальше.
Подробности — в `docs/`. Открывай файл своей области **до первой правки** в ней.

## С чего начать

1. [docs/WINDOWS.md](docs/WINDOWS.md) — цель порта, что чем заменить, грабли Windows и **задачи порта**
   (раздел «Задачи»). Чат мог оборваться: продолжай оттуда.
2. [docs/MAKAR.md](docs/MAKAR.md) — как работать с Макаром. Обязательно.
3. Мак-файл области из таблицы ниже, если переносишь эту часть.

[docs/TASKS.md](docs/TASKS.md) — журнал **мак-версии**. Здесь его не правь: ветки разойдутся
и при слиянии будет конфликт. Задачи порта ведутся только в WINDOWS.md.

## Стек

**Не выбран.** Пока Макар не выбрал, код не пишется. Первая задача — 2–3 варианта с плюсами,
минусами и одной рекомендацией (WINDOWS.md, «Сначала — решение Макара»). После выбора — записать
стек, команды сборки, тестов и запуска в WINDOWS.md и строку решения в [docs/DECISIONS.md](docs/DECISIONS.md).

## Ветка

- Код порта — только в `windows/` в корне. Мак-код не трогать: `<notes>/`, `NotesCore/`, `NotesSpeech/`,
  `Scripts/`, `<notes>.xcodeproj`. Нужна правка в общем коде — спросить Макара.
- Коммиты — в `Windows`, модуль `Windows`: `Feature Windows / Add vault picker`.
- **Ничего не сливать** ни в `Dev`, ни в `main` без Макара: «ниче не сливай без меня» (01.11.2026).
- Этот CLAUDE.md отличается от мак-версии. При слиянии с `Dev` его собирает Макар вместе с агентом,
  без автоматического выбора стороны.

## Нельзя никогда

- **Своя база с текстом заметок.** Источник правды — файлы `.md`. Индекс и кэш лежат в
  `%LOCALAPPDATA%\notes\` и пересобираются из файлов. В хранилище своих служебных файлов нет.
- **Портить хранилище для мака.** Без CRLF вместо LF, без переименований ради NFC/NFD и запрещённых
  имён. Файл, который не открылся, показать человеку и не трогать (WINDOWS.md, «Грабли»).
- **Свой сервер и аккаунты.** В сеть — только GitHub (если вошли по коду) и разовая загрузка модели.
- **Трогать чужие файлы в хранилище.** Приложение меняет только то, что меняет человек.
- **Модели в сборке и зависимости без вопроса.** Модели качаются по требованию, новая зависимость —
  только после слова Макара.
- **Секреты в коде, открытым текстом в файлах или реестре.** Токены и пинкод — только в
  Windows Credential Manager или DPAPI. Глобальный конфиг git и ключи SSH не трогать.
- **Пуш без слова Макара.**
- **Придумывать интерфейс.** Экраны рисует Макар. Мак-версия — образец, а новый экран или элемент
  под Windows без его фрейма не придумывать. Его фреймы в Figma не править.
- **Закрывать его запуск.** Свои процессы закрывать только по PID или по пути своей сборки,
  не `taskkill /IM` по имени.
- **Упоминать Obsidian** — нигде.
- **Говорить «должно работать».** Сделано — значит проверено на Windows: сборкой, тестом, снимком.
  Сессия не на Windows и собрать нельзя — так и сказать.

## Как сдавать работу

По порядку, без пропусков:

1. сборка под Windows без ошибок и без новых предупреждений
2. тесты порта зелёные; поведение сверено с тестами `NotesCore/Tests` и, если трогали доки,
   `cd NotesCore && swift test` (сторож документации — там, где есть Swift)
3. проверка вживую на Windows: снимок окна рядом с тем же экраном мак-версии или кадром Figma;
   хранилище тестовое, не настоящее
4. документация: раздел «Задачи» и «Журнал» в WINDOWS.md обновлены в том же ходе
5. коммит — сам, в `Windows`

## Как ведём работу

- **Не переспрашивать «что делаем дальше».** Закончил — бери следующую из WINDOWS.md, «Задачи»,
  и скажи одной строкой, что взял. Остановиться и спросить — только когда дальше решение Макара.
- **Каждая его просьба про Windows** сразу ложится строкой в WINDOWS.md, «Задачи», и уходит оттуда
  только в `[готово]` с коммитом или в `[ждёт Макара]` с вопросом.
- **Долгая работа — с короткими строками статуса.**
- **Документация коммитится сразу**, отдельным коммитом `Feature Docs / …`.

## Документация держит себя сама

`NotesCore/Tests/NotesCoreTests/DocsTests.swift` падает, если путь или ссылка в доках мёртвые или документ
из `docs/` не в таблице выше. Новый документ — строкой в таблицу. Этот файл — только маршруты и запреты.
