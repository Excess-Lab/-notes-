# Как устроено приложение

Технический контекст: что из чего сделано и почему. Что и зачем делаем — в [PRODUCT.md](PRODUCT.md).
Пока это **план**, кода почти нет. Когда решение принято и сделано, пометь его как «сделано»
и укажи, в каком файле оно лежит.

Автор раньше делал веб-сервисы, а приложения нет, поэтому рядом с некоторыми решениями стоит
параллель с вебом.

## Общая схема

```
Хранилище (папка с .md, git-репо)  ←  источник правды
        │
        ├── Редактор и дерево файлов (SwiftUI)
        ├── Sync: git commit / pull / push в фоне
        ├── Индекс поиска (кэш в Application Support, не в хранилище)
        └── Задачи → EventKit → Apple Calendar

Надиктовка (живёт отдельно от окна):
  глобальный хоткей → плавающая панель → микрофон → Whisper → буфер обмена
```

## Хранилище и доступ к файлам

- Приложение работает в **песочнице** (sandbox) macOS: без разрешения пользователя оно не видит его файлы.
  Доступ к папке хранилища даётся через окно выбора папки и запоминается через
  **security-scoped bookmark**. Веб-аналог: токен доступа к одной папке, который живёт между запусками.
- Изменения, сделанные снаружи (Obsidian, git pull), отслеживаются через FSEvents / `DispatchSource`.

## Git в папке и GitHub

**Решено:** локальный git плюс вход в GitHub по коду. Чужие настройки (`~/.ssh`, глобальный git config) не читаем.

- **Git — библиотекой (libgit2 через Swift-обёртку), а не системным `git`.** На чистом Mac git нет без
  Command Line Tools, а библиотека работает всегда и не запускает внешние программы.
- **Песочница остаётся включённой.** Нужен доступ к выбранной папке (security-scoped bookmark)
  и entitlement на исходящую сеть.
- **Инициализация:** если `.git` нет — `init`, свой `.gitignore` (служебное Obsidian, `.DS_Store`, видео/аудио),
  автор `notes <notes@local>` в `.git/config`, первый коммит «начало истории».
  Если папка в iCloud Drive — предупредить: iCloud может сломать `.git`.
- **Автокоммит:** FSEvents → пауза в несколько секунд → add изменённого → commit. Нет изменений — нет коммита.
- **Вход — GitHub Device Flow.** Работает без своего сервера и без client secret. Токен — в Keychain.
  Веб-аналог: вход на телевизоре по коду с телефона.
  - Код живёт **15 минут** (`expires_in: 900`, задаёт GitHub) — решили не сокращать. Код протух —
    показываем «код истёк» и «получить новый код».
  - Приложение опрашивает GitHub с интервалом из ответа (обычно 5 с, на `slow_down` +5 с).
  - Ушёл с экрана, нажал «назад» или закрыл окно — опрос останавливаем и забываем `device_code`.
    Тогда код, введённый позже, никому токен не даст.
  - Открыто: **OAuth App или GitHub App.** У OAuth App scope `repo` даёт доступ ко всем приватным
    репозиториям. GitHub App можно ограничить одним `notes` (токен на 8 ч, продлевается сам), но надо
    проверить, может ли он сам создать репозиторий от имени пользователя.
- **Репозиторий `notes` создаётся через GitHub API** (`POST /user/repos`, `private: true`). Если он уже
  есть (ответ 422), подключаемся к нему. Remote `origin` → `https://github.com/<логин>/notes.git`.
- **Push/pull по HTTPS с токеном**, после коммитов и при запуске. Конфликты не должны терять текст.

## Поиск по смыслу

- Тексты заметок режутся на куски (по абзацам или заголовкам), для каждого куска считается вектор (эмбеддинг).
- Запрос тоже превращается в вектор, ищем ближайшие по косинусной близости.
- Объём личного хранилища — тысячи заметок, поэтому хватает перебора в памяти; отдельная векторная база не нужна.
- Индекс хранится в SQLite в `~/Library/Application Support/…`, а не в хранилище: это кэш, в git ему не место.
  Для каждого файла запоминается хэш, и пересчитываются только изменившиеся файлы.

Кандидаты на модель (цель — маленький размер и нормальный русский):
- **`NLContextualEmbedding` от Apple.** Встроена в macOS и не весит в сборке ничего. Качество поиска нужно проверить.
- **Маленькая открытая модель через Core ML** (например, `multilingual-e5-small`, ~100+ МБ). Скачивается по требованию.

Сначала попробовать встроенную. Если качество на русском плохое, переходить на скачиваемую.

**А может, macOS сделает всё сама?** У Core Spotlight с macOS 15 есть семантический поиск
(`CSSearchableIndex` + `CSUserQuery`): приложение отдаёт заметки в системный индекс, а поиск по смыслу
делает система. Звучит идеально, но на форумах Apple разработчики пишут, что он находит только
буквальные совпадения, а на 26-й версии иногда молча ничего не возвращает (таймаут модели эмбеддингов).
Официального примера Apple так и не выпустила. Поэтому: **отдавать заметки в Spotlight стоит**
(они будут находиться и в системном поиске), но **свой поиск по смыслу строим на своём индексе**.
Перед этапом 4 стоит перепроверить на живом маке.

## Надиктовка

- **Хоткей.** Глобальная горячая клавиша через Carbon `RegisterEventHotKey` (или пакет вроде
  KeyboardShortcuts, который на нём построен). Разрешение Accessibility для этого **не нужно**.
- **Оверлей.** `NSPanel`, который не забирает фокус у текущего приложения и висит поверх всех окон.
  Волны рисуются от уровня громкости микрофона (SwiftUI `Canvas` / `TimelineView` или Metal-шейдер).
- **Микрофон.** Нужно разрешение (Info.plist `NSMicrophoneUsageDescription` и entitlement песочницы).
- **Распознавание.** Whisper локально (WhisperKit — на Core ML и Apple Silicon, или whisper.cpp).
  Альтернатива без скачивания в приложении — системный `SpeechAnalyzer` / `SpeechTranscriber` (macOS 26):
  модель ставит и обновляет сама система через `AssetInventory`. Минус: модель закрытая, а поддержка
  русского не подтверждена — проверить `SpeechTranscriber.supportedLocales` на живом маке.
  Автор хочет открытую модель, поэтому основной вариант — Whisper.
- **GigaAM v3 от Сбера** — вторая модель на выбор (решено). Открытая, лицензия MIT, только русский язык.
  По бенчмаркам на русском точнее Whisper large-v3, сразу выдаёт текст с пунктуацией. ~220–240 млн параметров,
  в INT8 ~300 МБ (полная ~850 МБ). Работает локально, без интернета. Как запускать на Mac:
  - **sherpa-onnx** — есть Swift API и готовые GigaAM-модели для русского (CTC и transducer). Первый кандидат.
  - **Core ML** — есть неофициальные сообщества-конвертации GigaAM v3 (работают на Neural Engine, быстрее).
    Перед использованием проверить лицензию и качество конвертации.
  - Облачный SaluteSpeech API от Сбера не берём: нужен аккаунт и интернет, это против local-first.
  - Для длинных записей (расшифровка видео) нужна нарезка по паузам (VAD) — в sherpa-onnx она есть.
- **Выбор модели** — экран в онбординге и в настройках: можно скачать несколько и переключать.
  Для русского по умолчанию советуем GigaAM, для других языков — Whisper.
  Модель **не входит в сборку**, она скачивается при первом включении надиктовки. Размер выбирается
  в настройках (base / small / …).
- **Результат.** Распознанный текст кладётся в `NSPasteboard`. Вставку в чужие приложения не делаем,
  поэтому разрешение Accessibility не нужно.

## Задачи и календарь

- Задачи лежат в Markdown (формат решаем).
- EventKit: нужно разрешение на календарь (Info.plist + entitlement).
- Для каждой задачи запоминается id события в календаре, чтобы при изменении обновлять событие, а не плодить новые.

## Размер приложения

- В сборку не кладём ни одной модели. Whisper и, если понадобится, эмбеддинги скачиваются отдельно, по включению функции.
- Каждую зависимость оцениваем, в том числе по весу.
