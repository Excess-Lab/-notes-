# Тесты и проверка

Что и как проверять перед сдачей. Порядок сдачи — в [CLAUDE.md](../CLAUDE.md).

## Тесты

Логика без UI живёт в пакете `NotesCore` и тестируется Swift Testing, без Xcode:

```bash
cd NotesCore && swift test
```

Распознавание речи — в `NotesSpeech`. Тесты с настоящими моделями включаются переменными, потому что
модели весят сотни мегабайт:

```bash
cd NotesSpeech && NOTES_GIGAAM_DIR=<папка распакованной GigaAM> swift test
```

`NOTES_WHISPER_TEST=1` дополнительно качает Whisper small (464 МБ) и распознаёт ту же запись.

Сейчас покрыто: git в папке (init на ветке main, .gitignore, коммиты, пустые коммиты, push в
локальный bare-репозиторий) и GitHub (разбор кода, ожидание, slow_down, истёкший код, отказ,
создание notes и уже существующий notes), синхронизация (подпись коммита, пустых коммитов нет,
отправка раз в сутки и только если есть что отправлять), слежка за папкой и pull с двумя «Маками»
(догнать сервер, слияние, конфликт — обе версии, правка сильнее удаления, второй Мак с чужой историей)
пинкод (придумать и повторить, несовпадение, только цифры, хеш с солью), умный вход
(перезапуск в течение 5 минут, 15 минут в фоне, пауза после 5 ошибок, пауза переживает перезапуск)
и горячая клавиша (подпись, порядок ⌃⌥⇧⌘, без модификатора нельзя, системные сочетания, хранение). Сеть в тестах
подменяется (`HTTPClient`), в GitHub не ходим; «сервер» для push — bare-репозиторий во временной папке.

- Описание теста в `@Test("...")` и комментарии — по-русски: тест читается как описание поведения.
  Имена файлов, типов и функций тестов — по-английски, как во всём коде.
- В комментарии пиши, что именно ломалось раньше. Иначе через месяц тест выглядит придиркой, и его удаляют.
- **Новый тест проверяется поломкой.** Сломай то, что он охраняет, убедись, что он упал, и верни как было.
- Новую логику — в `NotesCore`, а не во вьюхи: там её можно проверить.

## Живая проверка

- Своё приложение запускай из `build/` и закрывай **только свои процессы** (по пути `build/…`), не по имени:
  Макар часто тестирует параллельно из Xcode, и `pkill -x "<notes>"` убивал его запуск (19.10.2026).
- Нажатия клавиш и клики скриптом macOS не пропускает без доступа, а доступ — системная настройка Макара.
  Состояния экранов снимаем отладочными флагами (`-onboardingStep`, `-pinPreview`, `-dictationTestFile`),
  а живые нажатия (хоткей, ввод с клавиатуры, Touch ID) просим проверить Макара и так и пишем.
- Тестовые данные, которые трогают его настоящие (пинкод, токен), после проверки возвращаем как было
  или прямо говорим, что поменялось.
